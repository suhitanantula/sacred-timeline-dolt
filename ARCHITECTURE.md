# Architecture — Two Ledgers, One System

## The Problem

AI agents generate outputs. Institutions need to verify them. The gap between generation and verification is where trust lives — and right now, nobody's measuring it.

Sacred Timeline solves this with **two version-controlled ledgers** that work together:

1. **Git** — tracks what was created (documents, code, experiment artefacts)
2. **Dolt** — tracks whether it was trusted (CIQ measurements, governance decisions, capability progression)

Both are append-only. Both are branchable. Both have commit history. The difference is semantic: git knows *what changed*, Dolt knows *whether it mattered*.

## Why Two Ledgers?

A git commit tells you: "At 3:47pm, Yoda updated the briefing document."

A Dolt CIQ row tells you: "That update was accepted by the human. Trust score moved from 0.85 to 0.87. Curve: building."

Neither ledger is sufficient alone. Git without trust data is just audit theatre. Trust data without artefact history is contextless numbers. Together, they answer the question every institution is afraid to ask: *"Is our AI actually working?"*

## Data Flow

```
Agent performs action
        │
        ├──► Git: capture (commit to document ledger)
        │         message, hash, branch, files changed
        │
        └──► Dolt: CIQ log (insert to trust ledger)
                  agent_name, model, accept/override/reject,
                  trust_score, calibration_curve
```

When Sacred Timeline CLI auto-logging is active, this happens in a single command. The agent doesn't need to think about two systems — the CLI handles it.

## The Governance Layer

This isn't infrastructure. It's **the governance layer that sits between agents and institutions**.

### What makes it governance?

1. **Provenance** — every data point knows who created it (human, agent, or both)
2. **Audit trail** — Dolt commits are immutable. You can't retroactively change a trust score.
3. **Branchable decisions** — experiment with a new agent config on a branch. Measure trust. If it's good, merge. If not, discard. The institution sees the full experiment.
4. **Export manifests** — when something leaves the system (briefing sent, report published), the `exports` table records what went out, from which commit, approved by whom.

### What makes it different from a database?

- **Version control** — branch, merge, revert, diff. Like git but for data.
- **Time travel** — `dolt checkout kq8p1fib` to see the CIQ state at that exact commit.
- **Conflict resolution** — if two agents update the same experiment simultaneously, Dolt handles it like git handles merge conflicts.
- **SQL queryable** — standard MySQL-compatible SQL. No new query language to learn.

## Deployment Tiers

### Tier 1: Solo (Current)
- Single Dolt server on Mac Studio
- Yoda logs CIQ via CLI
- Git repo on GitHub, data local
- **Use case:** internal development, proof of concept

### Tier 2: Team (Abeer / UAE PMO)
- Dolt server inside UAE government infra
- Multiple agents logging to shared Dolt instance
- Gitea for document ledger, Dolt for data ledger
- Sacred Timeline CLI auto-logging enabled
- **Use case:** government innovation team running AI experiments

### Tier 3: Federation
- DoltHub as the remote — multiple teams pushing/pulling
- Cross-team trust comparison (anonymised CIQ aggregates)
- Export manifests for inter-agency sharing
- AAA assessments visible across the federation
- **Use case:** UAE federal government, then any government

## Security Model

- **Local first** — all data lives on-prem. No cloud dependency for Tier 1 and 2.
- **No auth on localhost** — Dolt default (root, no password) is fine for solo dev.
- **Tier 2+** — Dolt supports MySQL-style user accounts and permissions.
- **DoltHub** — optional remote. Private repos available. Data encrypted at rest.

## Relationship to Sacred Timeline CLI

The CLI (`sacred-timeline` repo) handles the git side. This repo handles the data side. They're separate codebases that share a vocabulary:

| Sacred Timeline CLI | Sacred Timeline Dolt |
|---|---|
| `sacred capture` | CIQ measurement inserted |
| `sacred experiment` | Experiment row created + branch |
| `sacred propose` | Proposal row created |
| `sacred timeline` | Trust progression queryable alongside git log |
| `sacred backup` | Both git push + dolt push |

See [CLI-AUTOLOG.md](./CLI-AUTOLOG.md) for the full integration spec.

## Relationship to Gas City

[Gas City](https://github.com/suhitanantula/gascity) is the multi-agent orchestration platform. It already uses Dolt (`.beads/dolt/`) for its own data plane.

Potential integration:
- Gas City agents log CIQ to Sacred Timeline Dolt instead of (or alongside) their own Dolt instance
- Shared trust measurements across Gas City workflows and Sacred Timeline experiments
- Unified governance view: "This proposal was generated by a Gas City agent, reviewed by a human, and the trust score is..."

This is a future consideration, not a current dependency.
